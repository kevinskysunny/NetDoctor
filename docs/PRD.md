# NetDoctor（网络体检）PRD

> 历史名称：`NetworkConsole Lite`（v1.0/v1.1 期间使用）。自 v1.2 起，产品对外名称统一为 `NetDoctor`，文档、支持包、时间线目录与网络请求标识一律使用新名称。
>
> **上架状态**：v1.1（构建 5）已在 App Store Connect 上架并可分发。商店显示名 `NetDoctor: Network Diagnostics`，Bundle ID `com.networkconsole.lite`，Apple ID 6801707344，SKU networkconsole-lite-0001，Team ID J84LGFK7GY，主要语言英语（美国），类别工具。v1.2 为增量升级，**上架标识符一律不可修改**（见 §8.7）。

## 1. 目标

将现有企业版 `NetworkConsole` 中通用、只读、可产品化的能力抽象为独立 macOS 应用，面向 Mac App Store 分发。

产品名：`NetDoctor`

中文定位：`网络体检`

一句话定位：`让普通 Mac 用户和轻度运维用户一键了解网络是否正常。`

## 2. 用户与场景

- 普通 Mac 用户：Wi-Fi 或网线突然断网、视频会议卡顿、网页打不开时快速定位原因。
- 轻度运维用户：需要确认接口、DNS、默认路由、VPN 和外网可达性的本地现状。
- App Store 审核人员：无需企业内网、账号或私有证书即可复现全部功能。

## 3. MVP 能力范围

### 3.1 必须包含

- 菜单栏状态图标和详情窗口。
- `NWPathMonitor` 驱动的网络路径状态：可用、不可用、Wi-Fi、有线、VPN、受限网络、按需网络。
- 活动接口摘要：接口名、接口类型、IPv4/IPv6、Wi-Fi SSID、链路状态。
  - 注：SSID 展示是否保留取决于沙盒实测结论，见 §8.4。
- DNS 解析器摘要：当前生效的 resolver 来源和服务器列表。
- 默认路由摘要：默认网关、活动接口。
- 外网可达性：对一组公开 HTTPS/TCP 端点执行只读探测。
- 延迟与丢包近似：对多端点、多轮请求统计 RTT 分位数、超时和失败比例。
- 健康分级：健康、警告、严重，并给出简明诊断说明。
- 本地事件时间线：最近诊断记录和网络变化记录。
- 本地支持包导出：脱敏后的快照、时间线和 App 版本信息。

### 3.2 明确禁止

- SSH、Clash、AOne、EasyConnect 等企业工具。
- 企业内网域名、IP、证书指纹或固定端口。
- DNS、路由、代理、VPN 的系统配置修改。
- LaunchDaemon、LaunchAgent、特权 Helper、管理员权限。
- Shell、Rust 子进程、外部诊断脚本。
- 自动上传诊断数据或遥测。

## 4. 技术约束

- Swift Package 结构，macOS 14+，SwiftUI。
- 只使用 `Network.framework`、`NWPathMonitor`、`NWConnection`、`URLSession` 和只读系统接口。
- 延迟和丢包采用应用层采样，不承诺 ICMP ping 能力；如后续验证沙盒内可安全支持 ICMP，再作为可选增强。
- 所有测试必须无真实网络依赖，使用 mock 注入。
- 默认不上传任何数据，导出文件由用户主动选择保存位置。
- 界面文本支持 8 种语言（zh、en、ja、ko、de、fr、es、pt）；**8 种语言全覆盖为产品目标**。zh 与 en 必须先行 100% 完整覆盖，其余语言在补齐过程中缺失键回退英文（运行时兜底保护），不得以中文兜底。

## 5. 性能目标

- 本地路径和接口状态：1 秒内出结果。
- 完整健康检查：健康网络 8 秒内完成。
- 网络变化触发：防抖后自动检查，但不自动修改任何配置。

## 6. 验收标准

- 在无网络、Wi-Fi、有线、VPN 状态下均能正确显示路径与接口状态。
- 详情页可查看 DNS、默认路由、外网探测、延迟与丢包近似。
- 菜单栏显示健康、警告、严重三种状态，不依赖企业内网。
- 审核人员可按 Review Notes 在 3 分钟内复现核心检查。
- `swift build` 和 `swift test` 通过。
- App 通过 App Sandbox、Hardened Runtime、隐私清单和签名校验。
- 8 种语言界面文本以中文 key 基线完整覆盖为目标，由自动化测试守护缺口清单持续收敛至零；任何语言不得以中文兜底（非中文语言缺失 key 时回退英文）。
- 将界面切换为任一支持语言后，不允许出现中文原文残留（NetworkCore 未本地化文案不得泄漏为界面文本）。
- 本地化补齐属纯增量变更（仅涉及 L10n 内容），不触碰上架标识符与权限，不构成升级审核风险。
- 升级版本号递增，上架标识符（Bundle ID / Apple ID / SKU）保持与 v1.1 一致。

## 7. 非目标

- 多设备管理、远程诊断、企业批量部署。
- 自动修复、DNS 写入、路由切换、VPN 启停。
- Windows、iOS、iPadOS 版本。
- 遥测、账号系统、云同步。

## 8. v1.2 需求增补（源自 2026-09-27 系统检查，见 docs/project-review-2026-09-27.md）

本节将系统检查发现的风险固化为可验收的需求，作为 v1.2 质量加固范围。

### 8.1 本地化完整性

**背景**：检查发现应用内本地化文件（`Localization.swift` 手写 dict）中 6 种语言（ja/ko/de/fr/es/pt）缺失 84~117 个界面文本 key。需澄清两点：
- 该缺失指**应用内运行时本地化的 key 覆盖**，与 App Store Connect 元数据语言（当前仅英语·美国）是**两套独立体系**，二者无需一致；应用内支持多于元数据语言是合规且常见的做法，App Review 不检查二者一致性。
- 补齐翻译属**纯增量变更**，不涉及 Bundle ID、签名权限、隐私声明，**不会影响版本升级审核**。

因此 8 语言全覆盖作为产品目标**保持不变**，不因已上架而降级；英文兜底仅作为补齐过程中的运行时保护层。

**需求**：
1. 全部界面文本必须在 8 种语言（zh、en、ja、ko、de、fr、es、pt）下完整覆盖，为本地化完成目标（缺口收敛至零）。
2. zh（中文基线）与 en（商店主要语言）先行 100% 完整覆盖，由自动化测试硬性守护。
3. ja/ko/de/fr/es/pt 按缺口清单分批补齐；补齐过程中缺失 key 回退**英文**作为运行时兜底保护——兜底链必须固定以 en 为最终兜底（修正当前 dict → en → zh 的链路，确保非中文用户不得回退中文）。
4. 后续新增界面文本时，zh/en 必须同步补齐；其余语言同步补齐，未补齐项进入缺口清单持续跟催。
5. 本地化变更只允许触碰 L10n 相关内容，禁止在同一提交中修改上架标识符与签名配置（见 §8.7）。

**验收条件**：
- [切换至 8 种语言逐一检查] → 全部界面文本（设置、详情、快捷检查、时间线、诊断卡片）显示对应语言或兜底英文，**无中文残留**，布局无破坏。
- [自动化测试断言各语言 key 集合] → zh 与 en 与中文基线 100% 一致；其余语言缺口清单可见并随版本收敛至零。
- [变更集审阅] → 本地化提交不包含 Bundle ID / entitlements / Info.plist 标识字段变更。

### 8.2 诊断结论语言中立

**背景**：检查发现 NetworkCore 的诊断结论、排查建议、时间线消息直接内嵌中文字符串，App 层再以中文字符串匹配二次翻译，文案稍改即失配，多语言用户将看到中文原文。

**需求**：
1. 诊断结论（verdict）、排查建议（advice）、时间线消息不得内嵌任何具体语言文案；必须以语言中立的标识（如枚举编码）标记类型，由界面层按当前语言渲染。
2. 时间线事件依赖结构化参数（状态、接口、计数、延迟等）重建本地化消息，原始 message 仅作日志与降级用途。

**验收条件**：
- [切换到任一支持语言并触发检查] → 诊断结论、排查建议、时间线消息均显示当前语言，与网络结果一致。
- [修改 NetworkCore 任一诊断结论的中文原文] → 不得导致任一语言界面回退显示中文（即翻译不再依赖原文匹配）。

### 8.3 支持包导出脱敏策略

**背景**：检查发现当前导出仅对 SSID 脱敏，接口 IP、DNS 服务器、网关完整保留，但界面文案宣称"对 SSID 与物理 MAC 脱敏"，范围表述与实际不一致。

**需求**：
1. 明确并记录支持包脱敏策略：SSID 必须脱敏；接口 IP、DNS 服务器、网关作为诊断信息保留。
2. 导出范围（保留字段/脱敏字段）必须与隐私政策声明及界面文案一致；文案不得承诺未实现的能力。
3. 时间线事件导出内容必须语言中立（见 §8.2），不得混入界面语言文案。

**验收条件**：
- [导出支持包] → SSID 以占位符替换；IP/DNS/网关按文档化策略保留；隐私声明与文案描述与导出结果一致。
- [查看导出的时间线] → 不包含依赖特定语言的内嵌文案。

### 8.4 SSID 能力（已上架现状与边界）

**背景**：系统采集器通过 CoreWLAN 读取 SSID，现有沙盒 entitlements 未声明 WiFi 信息权限。v1.1 已以此配置上架并通过审核，即**沙盒下 SSID 为空是已交付的现状**，无需重新验证。

**需求**：
1. **不新增** `com.apple.developer.networking.wifi-info` entitlement：新权限将改变签名配置并触发审核对权限用途的重新评估，收益低于风险。
2. 界面与导出对"无 SSID"做优雅处理：显示"未获取"等占位文案，不展示伪空白或误导状态。
3. 方案 A（申请 entitlement 以真正读取 SSID）仅在用户反馈构成明确产品价值后另行评估，不纳入 v1.2。
4. 相关界面与导出文案不得承诺未提供的 SSID 能力（与 §8.3 脱敏策略表述一并清理）。

**验收条件**：
- [沙盒构建运行并连接 Wi-Fi] → SSID 区域显示"未获取"占位文案，无空白/伪状态。
- [审阅界面与导出文案] → 不承诺未提供的 SSID 能力。

### 8.5 测试与质量

**背景**：检查发现测试仅覆盖 NetworkCore（16 例），本地化 key 完整性、本地化映射、语言解析、脱敏边界均无回归保护。

**需求**：
1. 本地化 key 完整性测试：以中文基线断言 zh 与 en 的 key 集合一致（CI 硬门禁）；其余语言输出缺口清单并纳入 CI 报告，缺失不阻塞当前版本但需可见并逐步收敛。
2. 本地化映射测试：诊断结论/建议/状态枚举到各语言文案的映射正确，且不依赖 NetworkCore 中文原文。
3. 语言解析测试：系统语言偏好到 `AppLanguage` 的判定正确。
4. 支持包脱敏测试：覆盖 SSID 脱敏与保留字段边界，断言与文档化策略一致。
5. 以上测试均不得依赖真实网络。

**验收条件**：
- [`swift test`] → 新增本地化与脱敏测试全部通过，且总测试时间保持无网络依赖。

### 8.6 品牌统一

**背景**：检查发现 v1.1 更名为 NetDoctor 后仍有残留：PRD 标题、支持包文件名前缀、时间线存储目录、UserDefaults 键名、HTTP User-Agent 使用旧名或硬编码版本号。

**需求**：
1. 产品对外标识统一为 `NetDoctor`：支持包文件名、时间线目录、网络请求标识不得与商店名称不一致。
2. 网络请求 User-Agent 必须反映真实产品名与版本号（从构建配置读取，不硬编码）。
3. 旧标识的历史数据（时间线文件）允许在迁移期内兼容读取，但新写入一律使用新标识。
4. 应用内显示名保持短名 `NetDoctor`，**不**改为商店全名 `NetDoctor: Network Diagnostics`；应用内名称与商店名称前缀一致即合规（App Review 关注误导性名称变更，短名不会构成不一致，且商店名称不在代码中变更）。
5. 品牌统一仅涉及代码内部标识与导出内容，**禁止**改动 Bundle ID、Apple ID、SKU、Team ID 等上架标识符（见 §8.7）。

**验收条件**：
- [导出支持包] → 文件名以 `NetDoctor-Support-*` 命名。
- [抓包或日志查看探测请求] → User-Agent 为 `NetDoctor/<版本号>` 格式。

**背景**：v1.1 已在 App Store Connect 上架并可分发（App 显示名 `NetDoctor: Network Diagnostics`，Bundle ID `com.networkconsole.lite`，Apple ID 6801707344，SKU networkconsole-lite-0001，Team ID J84LGFK7GY）。v1.2 为增量升级，必须保持上架标识不变并控制审核风险。
